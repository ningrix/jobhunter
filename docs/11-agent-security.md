# 11 Agent 安全边界（V2，V3 Phase 2 增补）

## 1. 绝对红线（代码与设计层面强制）

| 红线 | 实现保证 |
|---|---|
| 不绕过验证码 / 滑块 / 风控 | 驱动接口将 captcha 页定义为一等状态；流程层遇之即**暂停**（`captcha_blocked`），无任何绕过代码路径；MockDriver 专门模拟该场景并有测试断言「不填表不提交」 |
| 不绕过登录 | `login_wall` 同上；提示用户在**自己的浏览器**登录 |
| 不获取/存储平台账号、密码、短信码、Cookie、Session | 数据模型中无对应字段；Agent 流程无任何凭证输入参数；辅助导入仅接收 URL + JD 文本 |
| 不隐藏自动化行为 | 驱动不做指纹伪造/行为伪装；被平台识别即如实停止 |
| 不做未授权操作 | 每次提交前必须有 `wait_user_confirm` → 用户显式 `confirm(approve=true)` 事件；Level 2 自动执行器未启用 |
| 不读取无关数据 | 驱动接口仅暴露职位页语义操作（open/extract/clickApply/readForm/fill/submit/resolveCaptcha?），无任意 DOM/网络访问能力 |

## 2. 用户控制权

- **默认 Level 1**：Agent 完成准备后**必须暂停**等待确认；提交动作的用户确认事件（`userConfirmed=true`）持久化在 agent_events
- 一键拒绝：`confirm(false)` → 立即终止，无投递记录
- **用户接管（V3P2）**：确认阶段或安全验证阻断状态下，用户可 handover → `handed_over_to_user` 终态，Agent `driver.close()` 退出、不再执行任何操作；接管后 confirm/resolved 一律拒绝，不自动恢复，用户经手动投递/看板继续
- **人工复检 ≠ 自动重试（V3P2）**：验证码暂停后，仅当**用户声明并已在平台完成验证**时才允许复检（`captcha/resolved`），会话级上限 2 次；Agent 自身绝不自动重试、绝不代填验证码
- 策略引擎先行：即使 Agent 通过所有自动化步骤，投递落库仍会再次经过策略门禁（双重校验）

## 3. 失败处理

- 单来源失败 → 来源标记 unavailable/degraded，主系统不受影响（healthCheckAll 降级聚合）
- Agent 遇登录失效/验证码/页面变化/网络错误/元素缺失 → **停止并告知用户**，不无限重试（单会话 ≤12 步）；验证码场景的有限次人工复检是唯一例外，且每次复检都由用户显式触发并有事件审计
- **AI 降级（V3P2）**：AI 打招呼语任何失败（限额/网络/非法 JSON/超长/空响应）自动回退模板兜底，Agent 流永不因 AI 失败而中断
- **并发防护（V3P2）**：确认/复检带同步状态占位，并发重复请求被状态校验拒绝，杜绝双提交
- 优雅降级链：浏览器自动提取（未启用）→ 用户复制 URL/JD 辅助导入（可用）→ 手动录入（MVP 起可用）

## 4. 威胁与缓解

| 威胁 | 缓解 |
|---|---|
| Agent 被用于批量骚扰平台 | 每日投递上限（策略硬控）+ Level 2 未开放 + 单会话步数护栏 + 验证码复检 2 次上限 |
| 恶意 JD 内容注入指令 | 页面内容仅作为数据解析（UnifiedJob），不进入任何提示词执行上下文 |
| 刷 AI 配额 | AI 网关按用户日限额（9003/429）+ 全量计量；打招呼语场景同样受限额约束并降级兜底 |
| 越权操作他人职位/会话 | 全部服务层所有权校验；Agent 会话绑定 userId（跨用户 confirm/resolved/handover/读取均被 7103 拒绝，有测试覆盖） |
| 并发重复提交 | 确认/复检同步状态占位 + 状态机前置校验（有并发测试覆盖） |

## 5. 合规状态

- BOSS 等平台：无公开 API → 仅辅助导入（用户复制行为）；自动搜索/自动登录**未实现**且接入前必须逐平台合规评审
- Level 2 自动投递：引擎已支持判定，产品层面未开放；开放前需法务评审 + 显式用户开通流程
