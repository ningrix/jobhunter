## 2. 根因与方案

### 任务 1 SSE 订阅竞态
- **根因**：旧流程 `getTask(快照) → bus.subscribe()`。任务在两步之间完成时：快照=非终态，done 事件发出时订阅尚不存在（无人接收）→ 客户端永远收不到终态，只能等超时。
- **方案**：顺序反转为 **subscribe → 读快照 → 发送**。订阅生效后：发生在快照前的完成体现在快照（终态直接回放）；发生在快照后的完成经订阅送达。订阅初期事件先入缓冲区、快照发送后再回放，保证客户端顺序为「快照 → 事件」。`cancel()`（reader.cancel/浏览器关闭）与 `req.signal` abort 双路径统一走 finish 释放订阅与心跳。owner 校验、晚订阅终态回放、心跳、前端轮询兜底全部保留。

### 任务 2 Task 并发执行
- **根因**：旧 `executeTask` 只对 `succeeded` 短路；`running` 状态可被第二个执行者直接覆盖为 running 并再次运行 handler → **同一任务重复 AI 调用**（既有测试里 `runTaskAsync` + `await executeTask` 的组合一直在踩这个窗口）。
- **方案**：`queued/failed → running` 用单条条件 UPDATE（`.where(status IN (queued,failed)).returning()`）原子抢占，抢不到者轮询等待抢占者到终态（上限 20s）后返回同一行。SQLite 单写者保证语句级原子；进程内 better-sqlite3 同步执行进一步保证。**保留 failed 可重试语义**（claim 白名单含 failed），API 签名不变。

### 任务 3 Pricing Override 契约
- **根因**：`getPrice` 只遍历内置 `PRICE_TABLE`，覆盖表中**不在内置表里的前缀永远不生效**，与注释声明的「任意前缀」不符。
- **方案**：候选前缀 = 内置表 ∪ 覆盖表键（`*` 除外），按长度降序全局最长匹配；同前缀覆盖优先；`*` 仍为最终兜底；坏 JSON 静默回落不变。

## 3. 新增测试（+6，合计 275）

- SSE：并发双订阅各自恰好一次 done（快照必先行）；abort 后流及时关闭且不影响任务执行
- 并发：Promise.all 双 executeTask → handler 只跑一次（`ai_usage_logs` 恰 1 条、cost/token 口径一致）；后发起者等待抢占者终态
- Pricing：任意自定义前缀生效 + `*` 兜底；全局最长前缀（短覆盖不遮长内置、长覆盖遮短内置）

## 5. 已知未解决的生产风险（如实陈述）

1. **跨进程并发写 SQLite**：进程内 claim 原子性已证；但多实例部署时靠 SQLite 文件锁串行，未配置 busy_timeout，高并发写可能抛 `SQLITE_BUSY`。单实例部署不受影响；上 PG（V4.2+）根治。
2. **executeTask 等待上限 20s**：抢占者真实 LLM 执行超过 20s 时，等待方返回 running 中间行（不阻塞、不重复调用，但调用方拿到非终态）。当前所有路由均为 fire-and-forget + 前端 SSE/轮询，不受影响。
3. **价格表数值 NEEDS_VERIFICATION**：官方价随调，`AI_PRICING_OVERRIDES` 可运行时纠偏，但默认表需在首次真实计费前人工核对。
4. **SSE 经反向代理**：已带 `x-accel-buffering: no`，但未在真实 Nginx/CDN 后验证。
5. **git 未提交**：Mimosa commit 钩子阻塞问题仍待用户裁决，V4.0 + V4.0.1 + 审计会话改动全部在工作树中。

**V4.0.1 到此封版，不继续扩展功能。**
