# 01 产品需求（PRD）

## 1. 产品定位

**一句话**：把求职者从「Excel 记进度 + 满天撒网投简历」带入「一份主简历 × 按岗位定制多个版本 × 全流程可视化管理」的 AI 求职工作台。

- 目标市场：国内（中文界面，遵循个人信息保护法等合规要求）
- 项目性质：创业 MVP —— 架构可扩展但不过度设计，优先跑通核心闭环

## 2. 目标用户

| 画像 | 痛点 | JobHunter 的价值 |
|---|---|---|
| 0-5 年经验互联网/泛白领求职者（跳槽人群） | 简历一稿投所有岗位，命中率低 | 按 JD 生成差距分析，针对性定制简历 |
| 应届校招生 | 投了几十份记不清进度 | 看板式投递管理 + 节点提醒 |
| 转型/多方向求职者 | 多方向简历混乱 | 多版本简历 + 主简历机制 |

## 3. 核心闭环

```
粘贴 JD → AI 解析职位 → 与简历匹配打分（差距分析）
       → 针对性修改简历（AI 建议 + 人工确认）
       → 记录投递 → 看板跟进 + 节点提醒 → 数据复盘
```

## 4. MVP 功能清单（P0，已实现）

### 4.1 账号与画像
- 邮箱注册/登录（JWT + 刷新令牌轮换，httpOnly Cookie）
- 求职画像：期望职位、期望城市、期望薪资、工作年限、学历、技能标签

### 4.2 简历工作台
- 新建空白简历 / 上传解析（txt/md/pdf/docx → AI 结构化为统一 JSON）
- 结构化编辑：基本信息、个人优势、技能、工作经历、教育背景、项目经历
- 多版本管理（版本号自增，来源标记 manual/upload/ai），主简历唯一
- AI 诊断：0-100 评分 + 问题清单 + 优化建议（**建议必须用户确认后才生成新版本，AI 不直接改简历、不编造经历**）

### 4.3 职位中心
- 粘贴 JD 原文 → AI 结构化（岗位/城市/薪资/年限/学历/技能权重/职责/要求）
- 创建职位时未带结构化数据则自动发起解析任务
- 公司自动建档（按名称去重）、职位收藏、关键字搜索（标题/公司/JD 全文）、归档

### 4.4 智能匹配
- 规则评分器：技能 40%（加权命中率）/ 经验 25%（年限比例）/ 学历 15%（等级差）/ 城市 10% / 薪资 10%
- 差距清单（缺什么技能、差几年经验、学历/城市/薪资差距）
- 可选 AI 解读（异步任务，生成匹配总结与维度解读）
- 同一 (用户, 职位, 简历) 幂等更新；列表按分数倒序

### 4.5 投递看板
- 阶段：想投 → 已投递 → 笔试 → 面试 → Offer / 已挂 / 关闭（状态机校验合法流转）
- 事件时间线（创建/流转/备注自动记录），跟进备注
- 投递可关联使用的简历版本

### 4.6 提醒
- 站内提醒（可关联投递记录）、到期清单、完成/忽略
- 仪表盘高亮已到期未处理提醒（邮件通道预留接口，见架构文档）

### 4.7 数据看板
- 统计卡（简历/职位/投递总数/待办提醒）
- 投递漏斗（按事件去重统计到达各阶段的投递数）
- 近 8 周投递趋势、各阶段分布

## 5. 非功能需求

| 维度 | 要求 |
|---|---|
| AI 成本 | 全链路计量（ai_usage_logs）、单用户日限额（默认 200 次/天）、解析结果落库避免重复调用 |
| 隐私合规 | 简历属敏感个人信息：明示同意（注册条款）、最小化收集、密码 bcrypt 存储、账号注销级联删除（外键 CASCADE）、不向第三方共享 |
| AI 内容可信 | AI 输出全部落库可追溯（ai_tasks）、简历建议需人工确认、Prompt 明令禁止编造 |
| 性能 | 常规操作 < 1s；AI 任务异步化（任务轮询），不阻塞界面 |
| 可测试性 | 55 个 Vitest 用例，Mock Provider 离线可跑，接口测试免起服务 |

## 6. 明确不做（防范围膨胀）

- ❌ 爬取招聘平台数据（合规风险，职位源做成适配层留待二期评估官方合作）
- ❌ AI 代写/编造简历经历
- ❌ 代投简历、简历外发
- ❌ 社区/社交功能

## 7. 二期规划（不进 MVP）

AI 模拟面试（基于 JD 的模拟问答与评分报告）、求职 Copilot（对话式助手）、职位源适配层（浏览器插件采集/官方 API）、邮件提醒通道、移动端适配、多语言。

## 8. 验收标准（MVP）

1. 注册 → 完善画像 → 上传简历解析成功 → 结构化编辑 → AI 优化生成新版本 ✅（E2E 测试覆盖）
2. 粘贴 JD → 结构化入库 → 一键匹配得分数与差距清单 ✅
3. 创建投递 → 阶段合法流转 → 看板正确分组 → 时间线完整 ✅
4. 创建提醒 → 到期出现在仪表盘/提醒页 → 完成后消失 ✅
5. 仪表盘漏斗/趋势与实际投递数据一致 ✅
6. `npm test` 55/55 通过；`next build` 成功；浏览器全流程手工走查通过 ✅
