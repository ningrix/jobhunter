# 07 风险评估

## 风险清单（按严重度排序）

### 🔴 高

**1. 职位数据获取合规**
- 风险：爬取招聘平台数据违反 ToS 与《反不正当竞争法》，且有封禁/诉讼风险
- 缓解：MVP 仅用户手动录入/粘贴 JD，零爬虫；职位 `source/source_url` 字段预留适配层；二期如需批量数据，优先浏览器插件（用户本地采集）或官方 API 合作，上线前做合规评审
- 状态：已规避

**2. 个人信息保护（个保法）**
- 风险：简历属敏感个人信息，泄露或超范围使用面临处罚
- 缓解：注册明示同意、最小化收集（不采集简历外的社交数据）、密码 bcrypt、刷新令牌仅存哈希、账号注销外键级联删除、不向第三方共享、生产部署需 TLS + 静态加密（SQLite→PG 时启用磁盘加密）
- 状态：MVP 已做基础项；静态加密与安全审计留待生产化

**3. LLM 成本失控**
- 风险：解析/匹配/优化高频调用，成本随用户量线性上涨
- 缓解：AI 网关统一计量（ai_usage_logs 按 user/日）、日限额（AI_DAILY_LIMIT，超限 429）、解析结果落库避免重复调用、Mock Provider 开发零成本、接入真实模型后按 token 价格折算 cost 字段并加预算告警
- 状态：机制已就绪，真实价格表待接入

### 🟡 中

**4. AI 幻觉导致简历失真**
- 风险：模型编造经历/数据，用户直接采用后在面试中露馅，损害信任
- 缓解：AI 只输出「建议」（before/after/reason），必须用户确认才生成新版本；Prompt 明令禁止编造；UI 展示原文对照；二期可加「改写幅度检测」（建议与原文相似度过低时提示风险）
- 状态：已规避主要路径

**5. 单一模型供应商依赖**
- 风险：API 故障/涨价/政策变动导致核心功能不可用
- 缓解：Provider 接口抽象（AIProvider），Mock/兼容双实现；网关失败重试 3 次；架构上支持多 Provider 路由（当前主备开关，二期加自动故障转移）；ai_tasks.failure 可观测
- 状态：接口就绪，自动切换待实现

**6. 匹配质量冷启动**
- 风险：JD 结构化解析质量决定匹配上限；早期无标注数据
- 缓解：规则评分器维度透明可解释（reasons/gaps 落库）、支持用户纠错反馈（编辑结构化数据）、二期建立 100+ 条标注评测集回归 Prompt 改动、向量相似度作为补充信号（embeddings 表已预留）
- 状态：持续项

**7. 范围膨胀**
- 风险：「操作系统」概念过大，功能蔓延拖垮交付
- 缓解：PRD 明确「不做清单」（爬虫/代写/代投/社区）；模拟面试等一律进二期；MVP 验收标准固定
- 状态：已规避

### 🟢 低

**8. 文件解析兼容性**：简历模板千奇百怪，扫描件 PDF 无文本层 → 已做多级降级（txt 直读/pdf-parse/mammoth）+ 失败给明确错误（3003）引导用户改用粘贴/手动编辑；OCR 兜底留二期
**9. 异步任务堆积/超时**：进程内执行器无持久化队列 → 任务表状态机 + 前端超时提示；生产切 BullMQ 后加幂等消费与死信队列
**10. SQLite 并发写锁**：单写者模型，MVP 用户量下 WAL 足够 → 生产迁移 PostgreSQL（客户端单点封装，切换成本低）
**11. 安全（JWT 泄露/CSRF）**：access 15min 短时效 + httpOnly + sameSite=lax；刷新令牌轮换使被盗旧令牌快速失效；生产补充 CSRF 策略与速率限制中间件
**12. 演示数据误导**：seed 数据与真实用户数据同库 → seed 幂等且仅创建 demo 账号；生产环境禁用 db:seed
