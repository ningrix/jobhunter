## 1. 系统分层架构

四层结构：页面层 → 薄控制器层 → 领域服务层 → 基础设施层。请求自上而下、逐层收窄职责；AI 编排、职位来源适配、投递 Agent 是与领域服务平行的三个能力域。

```mermaid

        PAGES["九个页面<br/>login / dashboard / jobs / resumes / resume-detail<br/>applications / reminders / job-sources / discovery"]
        CLIENT["src/lib/client.ts<br/>统一 fetch：信封解析 · 401 自动刷新重试 · waitForTask 轮询"]

        RESUME["resume-service"]
```

要点：

- **薄控制器**：路由只做鉴权/校验/编排，业务规则全部下沉领域服务（见 docs/02 §2）。
- **AI 能力统一走网关**：Mock Provider 保证离线确定性测试，OpenAI 兼容 Provider 配置即切 GLM/DeepSeek。
- **Agent 永不绕过安全边界**：BrowserDriver 抽象约定登录墙/验证码如实上报即停（`src/server/agent/types.ts` 顶部注释即安全边界声明）。

## 3. 数据模型 ER 图

20 张表（`src/db/schema.ts`）。核心主线：`users → resumes（多版本）→ job_matches → applications（流转事件）`；`jobs` 由 companies 归档；`ai_tasks / agent_events` 是 AI 与 Agent 的审计底座。

## 4. 认证流程

JWT access（15 分钟）+ 随机刷新令牌（30 天，仅存 SHA-256 哈希，一次性轮换 + 可吊销），httpOnly Cookie 下发；前端 `lib/client.ts` 收到 401 自动刷新并重放原请求。

```mermaid
sequenceDiagram
    participant B as 浏览器 lib/client.ts
    participant A as /api/v1/auth/*
    participant D as SQLite

    B->>A: POST /login（email + password）
    A->>A: bcrypt 校验
    A->>D: 写 refresh_tokens（明文不入库，存 sha256）
    A-->>B: Set-Cookie jh_access（HS256，15min）<br/>Set-Cookie jh_refresh（30 天）

    B->>A: 业务请求（带 jh_access）
    alt access 有效
        A-->>B: 200 信封 {code, data}
    else access 过期
        A-->>B: 401
        B->>A: POST /refresh（带 jh_refresh）
        A->>D: 校验哈希 → 轮换（旧令牌吊销，发新对）
        A-->>B: 新 jh_access + 新 jh_refresh
        B->>A: 重放原业务请求
        A-->>B: 200
    end

    B->>A: POST /logout
    A->>D: 吊销 refresh_tokens
    A-->>B: 清 Cookie
```

## 5. AI 异步任务流程

四类任务（JD 解析 / 简历解析 / 诊断优化 / JD 定制）统一走 `ai_tasks` 表 + 进程内执行器（接口与 BullMQ 对齐，生产可换 Worker）；前端 `waitForTask` 轮询至终态。

```mermaid
flowchart TB
    A["页面发起<br/>POST /jobs/parse 等业务路由"] --> B["领域服务校验入参<br/>创建 ai_tasks：status=queued"]
    B --> C["进程内执行器 runner<br/>认领任务 → status=running"]
    C --> D["组装 Prompt（prompts.ts）<br/>调 gateway.generateText"]
    D --> E{"gateway 前置检查"}
    E -->|"超日限额 AI_DAILY_LIMIT"| F["任务失败 status=failed<br/>业务侧降级（如打招呼语回退模板）"]
    E -->|"放行"| G{"Provider"}
    G -->|"Mock（默认，离线确定性）"| H["返回结构化 JSON"]
    G -->|"OpenAI 兼容（GLM/DeepSeek）"| H
    H --> I["stripCodeFence + JSON.parse<br/>非法/空响应 → failed 或降级"]
    I --> J["status=succeeded，output 入库"]
    J --> K["前端 waitForTask 轮询<br/>GET /ai-tasks/:id（1s 间隔）"]
    K --> L{"终态?"}
    L -->|"succeeded"| M["页面取 output.data 展示<br/>（解析结果确认后入库）"]
    L -->|"failed"| N["页面提示，可重试"]
```

## 6. 职位导入与去重流程

来源无公开 API 时由用户复制 URL+JD，适配器做 `assistedImport`（仅辅助，不碰用户平台凭证）；normalizer 规范化后计算内容指纹，deduplicator 三级判定。

```mermaid
flowchart TB
    U["用户在职位来源页<br/>粘贴 职位 URL + JD"] --> S["选定适配器（registry）<br/>mock ｜ boss ｜ liepin ｜ zhilian ｜ lagou ｜ job51"]
    S --> N["normalizer 规范化<br/>剥 HTML/压空白/薪资统一 15-25K≡15K~25K≡1-2万<br/>公司去法律后缀 · 城市归一 · 小写"]
    N --> FP["内容指纹 = SHA-256(规范化文本) 截 40 位<br/>存 jobs.fingerprint"]
    FP --> D1{"deduplicator 一级：<br/>source + source_job_id 精确命中?"}
    D1 -->|"命中"| EX1["EXACT_DUPLICATE<br/>返回已有职位"]
    D1 -->|"未命中"| D2{"二级：内容指纹命中?<br/>（跨平台同内容）"}
    D2 -->|"命中"| EX2["EXACT_DUPLICATE"]
    D2 -->|"未命中"| D3{"三级：公司+职位+城市一致<br/>但内容不同?"}
    D3 -->|"命中"| PS["POSSIBLE_DUPLICATE<br/>仅提示，不自动合并（高置信才合并原则）"]
    D3 -->|"未命中"| NEW["NEW → 创建 jobs + 公司自动建档"]
    EX2 --> R["返回 {job, dedupe, warnings}<br/>自动用主简历计算匹配度"]
    PS --> R
    NEW --> R
```

## 7. 匹配与推荐流程

评分器五维加权（`match-scorer.ts`：技能 0.4 / 经验 0.25 / 学历 0.15 / 城市 0.1 / 薪资 0.1），结果落 `job_matches`；推荐接口按分数实时分桶，不改动评分器语义。

```mermaid
flowchart TB
    R["选择简历 × 职位"] --> S["match-scorer 五维评分"]
    subgraph W["维度权重"]
        W1["技能 0.4"]
        W2["经验 0.25"]
        W3["学历 0.15"]
        W4["城市 0.1"]
        W5["薪资 0.1"]
    end
    S --> W
    S --> M["job_matches 落库<br/>（可选 AI 解读：strengths/gaps/risks）"]
    M --> B{"recommendation-service 分桶<br/>（POST /recommendations/refresh 重算活跃职位）"}
    B -->|"total_score ≥ 85"| B1["strong 强烈推荐"]
    B -->|"70 ≤ score < 85"| B2["recommended 推荐"]
    B -->|"score < 70"| B3["confirm 待确认"]
    B -->|"已有 application"| B4["applied 已投递"]
    B1 --> D["职位发现页五桶展示<br/>圆环评分徽章 + 差距清单<br/>→ Agent 半自动投递 / 手动投递"]
    B2 --> D
    B3 --> D
    B4 --> D
```

## 8. Agent 投递状态机

Level 1 半自动投递（`apply-flow.ts` + MockBrowserDriver）：全程经策略门禁，提交前必须用户确认；登录墙/验证码如实上报即停、绝不绕过；接管不可逆。

```mermaid
stateDiagram-v2
    [*] --> running: POST /agent/runs（jobId+resumeId）

    state running {
        [*] --> open_page: BrowserDriver.open
        open_page --> login_wall_stop: kind=login_wall（如实上报即停）
        open_page --> job_detail
        job_detail --> click_apply
        click_apply --> captcha_blocked: kind=captcha
        click_apply --> apply_form
        apply_form --> policy_check: 读表单+JD
        policy_check --> policy_reject: REJECT（硬性不满足）
        policy_check --> need_confirm: 软性规则<br/>REQUIRE_USER_CONFIRMATION
        policy_check --> content_gen: ALLOW（白名单/全部满足）
        need_confirm --> content_gen
        content_gen --> fill_form: 打招呼语<br/>useAI=true 走 AI，失败降级 template
        fill_form --> wait_user_confirm: 表单就绪（confirm 前不提交）
    }

    wait_user_confirm --> awaiting_confirmation

    awaiting_confirmation --> submitted: 用户确认 → driver.submit → 成功
    awaiting_confirmation --> failed: 提交失败
    awaiting_confirmation --> rejected_by_user: 用户拒绝
    awaiting_confirmation --> handed_over_to_user: 我自己来投（handover，不可逆）

    captcha_blocked --> awaiting_captcha_check: blocked_reminder_created<br/>自动创建待处理提醒
    awaiting_captcha_check --> running: 用户在平台完成验证后<br/>POST /captcha/resolved 复检（≤2 次，sticky 未通过不重试）
    awaiting_captcha_check --> handed_over_to_user: 接管处理

    login_wall_stop --> handed_over_to_user: 需登录提醒 + 接管
    submitted --> [*]
    failed --> [*]
    rejected_by_user --> [*]
    handed_over_to_user --> [*]
```

安全红线（docs/11、13）：不绕过验证码/登录/MFA/风控；不隐藏自动化；默认 Human-in-the-loop；验证码复检上限 2 次（`MAX_CAPTCHA_RESUMES`），未真正通过保持 blocked（sticky）。
